# 05E 任务栏显隐观测工具

本工具使用 Host 实验适配器，为每块显示器的底部 Explorer 任务栏建立一个真实、透明、禁用输入且不激活的子窗口，保持 `WS_VISIBLE`。它不显示组件，也不改变正式 Host 的启动或窗口路径。05D 暂时阻塞，当前按维护者确认的 05B 基线测试 05E。

**2026-09-19 实测状态：当前候选不通过。** 用户确认 F11 全屏时主屏任务栏实际消失，但 `observe-20260919-233608-a843f1` 的两屏各 4799 次采样均为 VisibleCandidate，逻辑可见与两种 GDI 裁剪信号全程未变。本工具当前只保留作诊断，不可据此接入小组件显隐；这个结论针对本候选和已测环境，不代表所有可能的探针机制均已否定。

## 启动与停止

在仓库根目录的 PowerShell 中运行（需要 .NET 10）：

支持 Windows PowerShell 5.1 和 PowerShell 7。该目录的 `.ps1` 脚本必须保存为带 BOM 的 UTF-8，避免 Windows PowerShell 5.1 按系统代码页误读中文；`.editorconfig` 已规定此编码。验证脚本会经过与用户相同的 `Run.ps1` 入口。

```powershell
# 首轮只观测；返回进程 ID、日志目录和提前停止用的文件路径。
./tools/TaskbarVisibilityLab/Run.ps1 -Mode observe -Seconds 120

# 关闭探针的对照，使用相同秒数和采样周期，分开运行。
./tools/TaskbarVisibilityLab/Run.ps1 -Mode baseline -Seconds 120 -NoBuild

# 自动化进程验证：仅创建本程序的隐藏测试父窗口，不挂到 Explorer。
./tools/TaskbarVisibilityLab/Verify.ps1
```

程序不弹出窗口，时间到自动清理并退出。需要提前停止时，在返回的输出目录创建 `stop.request`：

```powershell
New-Item -ItemType File -Path '<本次输出目录>/stop.request'
```

每次使用新目录，日志不能覆盖旧实验。只运行一份 observe 实例；正式 Host 和其他 MTP 实验应先由维护者正常退出，避免混入已有独立窗口对探针的干扰。退出后读取 `summary.json`；仅有 `observations.jsonl` 不能证明已正常结束。`error.txt` 表示本次未成功；不得把失败会话算通过。

## 记录了什么

- `session`：模式、OS、架构、PID、UTC、单调时钟频率、请求采样周期。
- `sample`：各屏显示器 ID、分辨率和位置、DPI、任务栏/探针句柄、进程/线程 ID、父链、样式、矩形、alpha、cloak、默认 DC 和带兄弟裁剪 DC 的原始区域类型/包围框、完整性判断、生命周期代次。
- `trace`：窗口消息、相关任务栏/探针 WinEvent、前台切换触发、创建/销毁时序。事件包含本地单调时间、WinEvent 原始毫秒时间和每会话序号。队列有界，丢弃计数公开；丢事件的场景需重测，不能静默当完整记录。
- `candidate_change`：每屏 GDI 候选信号变化，**不是**任务栏实际像素变化或组件显隐完成时间。
- `resources` / `summary`：本进程 CPU 时间、单核占比、私有内存、工作集、GDI/USER 资源及采样次数/最大间隔。`endToEndLatencyMs` 留空，人工验收状态保持 pending。

固定 4×4 客户区探针从 (1,1) 开始，不承载内容。先隐藏创建，设置 `WS_EX_LAYERED` 且 alpha=0，成功后显示；`WS_DISABLED`、`WS_EX_NOACTIVATE`、`WS_EX_TRANSPARENT` 和命中测试共同防止输入。此处“显示”仅指逻辑可见位，不应出现任何可见图形。

`VisibleCandidate` 只说明本次读取的逻辑可见、有效父级、透明属性、底部任务栏/探针完整位于屏内和简单 GDI 裁剪信号一致。复杂区域的外接矩形不能证明没有空洞，因此返回 Unknown。两个 DC 信号冲突、关系丢失、采集超过 100 ms 或读取变化时也返回 Unknown。全屏覆盖可能完全不改变这些信号，这正是本实验需要识别并证伪的风险，不能通过前台全屏推测弥补后宣称探针可靠。

## 第一轮人工观测

先记录 Windows 版本、实际屏幕排列、各屏分辨率/DPI、自动隐藏配置，以及是否使用第三方任务栏；未覆盖配置保持未验证。每项至少重复五次，逐屏记录“实际看见什么”与日志信号是否一致：

| 场景 | 要核对的事实 |
| --- | --- |
| 桌面与普通最大化 | 没有探针图形/边框，不抢焦点，任务栏原位置的输入正常 |
| 自动隐藏、边缘唤出 | 收起/滑动期间与完整露出后的候选信号可区分 |
| 全屏覆盖、全屏中唤出任务栏 | 任务栏被盖住时不能仍报告 VisibleCandidate；唤出能恢复 |
| A 屏全屏、B 屏桌面 | 各屏结果不同且互不复制 |
| A 屏唤出、B 屏收起 | 各屏信号分别变化 |
| Alt+Tab / Win 键 | 信号跟随实际任务栏；前台事件本身不作真值 |
| Explorer 重建 | 维护者自行重启；旧句柄失效先 Unknown，新代次重建，无遗留探针 |
| 显示器断开/恢复、DPI 调整 | 对应探针清理/重建，其他屏幕不受影响 |
| 正常结束和提前停止 | summary 清理确认，任务栏无遗留输入区域或图形 |

可以在第二个 PowerShell 中为稳定场景做标记：

```powershell
./tools/TaskbarVisibilityLab/Mark.ps1 -OutputDirectory '<本次输出目录>' -DisplayId '\\.\DISPLAY1' -Observed 全屏覆盖 -Note '实际任务栏完全不可见'
```

DisplayId 使用 sample 中实际值；标记写入 `human-marks.jsonl`。人工按键包含反应时间，不能用它计算毫秒级端到端延迟。保留完整日志和具体反例；若全屏覆盖前后仍是同一候选信号，直接记录信号不成立，不把“逻辑可见”解释成“实际可见”。

## 信号确认后的第二轮

按 05E 票据，第一轮结果经维护者确认前不连接真实独立组件。Host 中已提供 `ProbeDisplayGate`：只有已验证候选、当前用户显示偏好和新鲜样本同时满足才允许显示；其他情况只暂时抑制该屏，保持组件数据和偏好。该接口的自动化测试不代表已经接入产品窗口。

人工确认信号有效后，再接通独立窗口实验消费者并测试：用户开关/状态保留、显示区域完整露出后显示/开始裁剪即隐藏、探针被组件覆盖是否造成闪烁、多屏不同状态组合。正式窗口路径仍不接入实验。

端到端测量需同时包含“实际任务栏组件区域完整露出/开始被裁剪”和“独立组件实际完成显示/隐藏”两个时刻。建议用 240 fps 外部相机同时拍到同屏任务栏区域与组件，记录帧号差及每端 ±1 帧的不确定度（差值最多约 ±8.34 ms）；低帧率录制无法支持 25 ms 目标判定。每屏每场景至少 20 次显示和隐藏，分别列最大值、P50/P95、误差和失败样本；上界不超过 100 ms 才算达标，25 ms 是优化目标。跨屏分别计时，不以不同刷新率的帧号直接相减。工具中的采样耗时、最大采样间隔和人工标记不能代替此测量。

资源对照使用相同秒数、间隔和相同人工操作顺序的 baseline / observe 会话；分别报告 CPU、内存、句柄和实际采样次数。本轮不设资源硬门槛，短暂 fixture 数据也不能推广为任务栏常驻开销。

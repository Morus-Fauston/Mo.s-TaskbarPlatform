# 05F 人工验收手册

这份手册配合真实的 Taskbar Island Lab 使用。演示内容为本票的 WinUI Button、ToggleSwitch、Slider、计数动画及 Popup/Flyout。目的：让维护者确认内容岛路线在已测 Windows 环境中的原生外观、任务栏同步、输入和成本。

**2026-10-01 结论快照：维护者已批准当前笔记本单屏最小验证通过并收口。** 材质、性能补测、UIA 详细取证和外屏覆盖保留，FFO 重叠及透明空白不穿透点击为低优先级限制；不代表正式路线采纳或完整常驻性能达标。范围调整与当前状态以 [05F 票据](../../.scratch/二期开发/issues/05F-WinUI内容岛任务栏承载最小验证.md)为准，后续事项见 [05F 保留项](../../Docs/待办与预案/二期遗留问题与风险清单.md#05f-单屏验证收口保留项2026-10-01)。本次无需重复已通过操作；以下流程保留供未来获授权的复验使用，观察模板不预填通过。看到窗口、命令显示 PASS 或父句柄正确，仍不能代替对应环境的人工确认。

## 1. 先启动演示

在资源管理器打开本目录，双击 [Start-Demo.cmd](Start-Demo.cmd)。也可在仓库根目录的 PowerShell 执行：

~~~powershell
& tools/TaskbarIslandLab/Demo.ps1
~~~

菜单如下；每次结束一个实例再进入下一个：

| 编号 | 内容 | 用途 |
| --- | --- | --- |
| 1 / 2 / 3 | 自有窗口，none 材质，alpha 1 / 0.5 / 0 | 不透明、半透明、透明三组对照 |
| 4 / 5 | 自有窗口，Desktop Acrylic / Mica | 材质观察 |
| 6 | 普通 WinUI 顶级窗口，再选配置 | 同内容基线，定位是否为内容岛承载差异 |
| 7 | 人工选择 Explorer 任务栏与配置 | 真实嵌入、输入、隐藏、全屏和重建 |
| 8 | Explorer，none / alpha 0.5 / 30 Hz，10 分钟可见采样 | 基础视觉与行为成立后的性能检查 |
| B / E / M | 打开彩色动态背景 / 本轮证据目录 / 本手册 | 辅助入口 |
| 0 | 退出菜单 | 不会标记票据完成 |

普通演示默认 0 Hz，按钮计数不会被定时刷新覆盖。启动前有 3 秒准备时间；你可以切回记事本或背景浏览器，观察显示是否抢焦点。每个普通实例最多运行 30 分钟，超时后正常关闭。

**停止当前实例：** 回到启动终端按 Q，或右键小窗口的「+1」→「关闭实验」。停止后回到菜单。不要直接关闭终端代替清理。若当前终端不支持单键读取，在另一个 PowerShell 窗口执行（填当前子目录，而非总目录）：

~~~powershell
& tools/TaskbarIslandLab/Stop.ps1 -OutputDirectory '这里填当前实例的完整证据目录'
~~~

若提示可执行文件不存在，先执行以下命令，成功后重开菜单：

~~~powershell
dotnet build tools/TaskbarIslandLab/TaskbarIslandLab.csproj --configuration Release
~~~

运行依赖与版本见 [README](README.md)。若 Windows 脚本策略阻止启动，保留报错并按本机允许的策略运行，不需要管理员权限或修改系统全局策略。初始化失败、缺 Runtime 或原生崩溃均应保留日志，不记作视觉失败。

## 2. 记录规则与检查顺序

启动器自动新建仓库内的 .scratch/二期开发/verification/05F/manual-时间戳/，包含：

- **人工观察记录.md**：由你填写。每一行按模式分别注明结果，例如「owned 通过；explorer 失败」。
- **session.json**：分支、提交、工具 DLL 哈希、OS、PowerShell 等身份信息；未提交代码须结合 DLL 哈希识别。
- 每次运行的编号子目录：launcher.json、events.jsonl、summary.json、启动器输出与错误；cases.jsonl 记录运行索引。

第一轮先做 A–D，通常十几分钟可得到初步结果；再做 E–F。G 的单次 Explorer 30 Hz 测量约 10 分 45 秒，另有启动时间。首次准备、发现失败、完整配对或未覆盖环境可能需要更久，可分次完成。

填写环境：Windows build、GPU/驱动、屏幕标识、分辨率、缩放、刷新率、HDR、系统主题/透明效果、任务栏自动隐藏、电源模式。先在一个选定屏幕完成；不把单屏结果扩大为多屏通过。

| 写法 | 何时使用 |
| --- | --- |
| 通过 | 你确实操作并观察到下文标准，附模式、配置和证据 |
| 失败 | 实际行为与标准不符，写出首个反例和复现步骤 |
| 未知 / 待人工 | 尚未执行、没有所需工具、环境不具备或看不清，说明原因 |

**第一道关口：** 任一关键不透明、崩溃、DPI 重置、输入失效、不同步或不可接受成本出现，就保留该反例、停止扩大验证范围。无需为了取得“通过”继续做长时性能或改 UI 路线。失败也能形成有效的实验结论。

## A. 透明是否真的成立

**前置：** 菜单 B 打开 [Backdrop.html](Backdrop.html)，浏览器最大化。用同一动态彩色背景，保持系统主题和缩放不变；视觉阶段可以截图或录制。

1. 启动菜单 1。观察控件之间的背景区域：alpha 1 应遮住后方条纹，作为不透明反例。保存截图和子目录。
2. 关闭实例，启动菜单 2。观察 alpha 0.5：后方条纹应能透出，并与前景色混合；控件本身仍清晰。
3. 关闭实例，启动菜单 3。观察 alpha 0：空白底应让后方真实背景透出，不能是固定黑底、白底或窗口内部画的假背景。移动背景中的条纹时继续观察。
4. 对比三组截图，在观察表分别填写结果。三组看起来相同，也要如实记录。

**失败取证：** 一张包含窗口边缘和后方条纹的截图，注明 none、alpha、模式、系统透明开关；保留对应日志。不要用“alpha 参数已设置”替代视觉判断。

小窗口固定为 260 × 56 DIP；144 DPI 时为 390 × 84 像素。默认位于屏幕像素坐标 80,80，没有实现拖动交互。被背景说明文字遮住或位置不合适时，可关闭实例后单独指定坐标：

~~~powershell
& tools/TaskbarIslandLab/Run.ps1 -Mode owned -Scenario manual -Hz 0 -Material none -Alpha 0.5 -X 200 -Y 300
~~~

该命令会另建证据目录；把输出路径补进观察表。改变位置不改变内容尺寸。

## B. 材质与主题

**前置：** A 的背景和环境保持不变。

1. 菜单 4 查看 Desktop Acrylic。比较后方真实彩色条纹：应能看到与外部背景有关的模糊/着色变化，而非仅在应用内部模糊。分别记录激活与未激活、系统透明效果开/关时的实际表现。
2. 菜单 5 查看 Mica，记录底色、主题和激活变化。**Mica 是不透明材质，不能用它证明透明要求通过。**
3. 在 Windows「设置 → 个性化 → 颜色」中分别切换浅色/深色，以及「透明效果」。观察现有实例是否响应，必要时另开实例比较并明确区分“实时响应”和“重开生效”。验完恢复原设置。
4. 无材质、Acrylic、Mica 分开填写；记录退化为纯色等行为以及触发条件，不把所有状态合成一个通过。

**通过标准：** 所需材质的实际外观及主题行为符合你的目标；透明与不透明能力独立判定。日志中的材质分配成功只是 API 证据。

**失败取证：** 同位置、同背景的对比图；系统开关、激活状态和对应实例目录。

## C. 输入、焦点、热区与浮出内容

**Popup 修复后的单项复验流程（2026-10-01 已获维护者确认通过）：** 关闭旧实例后重开本目录 Start-Demo.cmd，选 7 → 2 → 当前任务栏。右键 +1 出现的两项菜单是 Flyout；点“切换最小 Popup”后，另一块含“Popup 越界与焦点夹具”和“关闭 Popup”的面板应优先出现在 +1 上方并完整位于屏内。依次检查按钮关闭、再次打开后点外关闭、任务栏自动隐藏时无孤立残留，以及打开面板后在终端按 Q 结束时一起消失。维护者已回复“没有问题”，见 [人工复验记录](../../.scratch/二期开发/verification/05F/manual-20261001-201348-796/人工观察记录.md)；本次不用重测。未来复验时再回传观察与新目录。材质后置、FFO 重叠低优先级、隐藏成本补采暂缓的决定保持不变。

**前置：** 用菜单 2，0 Hz。先在记事本输入几个字，再启动演示并切回记事本等它显示。

| 检查 | 操作 | 通过标准 / 需要记录 |
| --- | --- | --- |
| 无激活 | 小窗口出现前在记事本准备输入；出现后继续输入 | 初次显示未抢走前台；任务栏恢复时再测一次。主动点击之后的焦点另记 |
| Button 与动画 | 点击 +1 三次，观察计数文字 | 每次加 1；文字约 450 ms 淡入；无丢点击、卡死或视觉异常 |
| ToggleSwitch | 来回切换三次 | 开关状态与鼠标操作一致，原生状态反馈可见 |
| Slider | 拖至左右端和中间；聚焦后按方向键 | 值和滑块位置响应，未被父级截获 |
| 键盘导航 | 点入控件后 Tab、Shift+Tab，按空格/方向键操作 | 可达控件有可见焦点、动作正确、没有焦点困住；无法进入焦点也记失败 |
| 透明空白热区 | 切到菜单 3，将后方可点击内容置于控件间空白下，分别点击空白和控件 | 记录空白是否穿透、控件是否仍可点击；视觉透明不等于鼠标穿透，不要把拦截写成通过 |
| UIA | 已装 Accessibility Insights for Windows 或 Windows SDK Inspect 时，定位本工具控件树 | 检查“实验计数”“增加本地计数”“本地开关”“本地滑块”的名称、角色、状态及可操作性；未装工具则未知 |
| Flyout | 右键 +1，点击外部关闭，再打开 | 检查菜单是否越过小窗口边界、是否被裁剪、焦点/关闭是否正确 |
| Popup | 右键 +1 → 切换最小 Popup，点其中关闭按钮，再打开后点外部 | 检查越界、裁剪、内部按钮、轻触关闭、焦点。没有显示也要记录 |
| 残留 | 浮出内容打开时停止实验；E 中再测任务栏隐藏 | 不留下菜单、Popup、孤儿窗口或截获点击的区域 |

本工具没有提供“禁用全部控件”入口，不需要凭空补做这项。Popup 与 Flyout 分开记录；是否使用独立 HWND 需要窗口检查工具核对，现有 Popup 开关事件不能证明这一点，没有核对则记未知。

**失败取证：** 操作顺序、失效控件、当时前台应用、截图/短录制及子目录；日志中的 button/toggle/slider/popup 事件可辅助定位，但不替代实际输入体验。

## D. 普通 WinUI 顶级窗口对照

1. 菜单 6，选择与 A–C 相同的材质和 alpha。
2. 重复透明、材质、按钮/开关/滑块、键盘与 Popup 的相关检查。
3. 在观察表把 owned 与 top-level 并排记录。相同问题可能是共同内容或运行环境的限制；只在 owned 出现的问题是承载差异线索，仍需诊断才能确认根因。

## E. 真实任务栏、全屏与自动隐藏

**前置：** A–D 没有阻止继续的关键反例，选定一个底部任务栏。记下原自动隐藏设置。

1. 菜单 7，先选配置；启动器列出屏幕名、任务栏 HWND 和类名。**由你选择实际要测试的任务栏编号**，再输入横坐标 X，避免遮挡常用任务栏按钮。直接回车可取消选择。
2. 观察控件确实位于选定任务栏中，而非旁边另一个浮动窗口。检查实际父链/DPI 日志并配合视觉确认。跨进程初始化失败时保留该目录，不把任何独立窗口当作嵌入成功。
3. 在任务栏里重新做 A–C 的所需项目，尤其透明、输入、无激活、空白热区与浮出内容。自有窗口结果不能代替本步骤。56 DIP 内容可能高于实际任务栏：必须记录顶部/底部是否被裁掉、Slider 是否可点，不把裁剪默认为通过。
4. 按下表顺序做动态反例；观察任务栏与实验内容是否一起变化。

| 场景 | 人工操作 | 合格现象 / 反例 |
| --- | --- | --- |
| F11 覆盖与恢复 | 背景浏览器按 F11 进入全屏，再按 F11 返回，重复两次 | 实验不悬在全屏内容之上，恢复时随任务栏正确出现，没有滞留或抢焦点 |
| 全屏唤出任务栏 | 浏览器仍在 F11 时将鼠标移到屏幕底边；若此环境可唤出任务栏，观察后移开 | 实验跟随任务栏，不单独残留；无法唤出则如实记录环境和未知，不能假设通过 |
| 自动隐藏 | 设置 → 个性化 → 任务栏 → 任务栏行为，开启自动隐藏；鼠标反复进入/离开底边 | 内容与任务栏同步进入/离开，无独立悬浮、明显脱节、热区残留 |
| 中途反向 | 任务栏展开未结束就移开，收起未结束就移回，反复几次 | 两者反向行为一致，不跳位、不停在半路 |
| Alt+Tab / Win | 切换应用、打开/收起开始菜单、回到原应用 | 无持续抢前台、意外遮挡或多余 Alt+Tab 项，记录异常 |
| 移动与裁剪 | 观察任务栏收放时自身的移动/裁剪；若当前系统支持移动任务栏，可另记一次 | 内容位置与父级一致，不把本工具当可拖动产品；没有条件的扩展场景写未覆盖 |
| 浮出内容残留 | Popup/Flyout 打开时分别触发自动隐藏和全屏 | 不留下孤立浮出内容、不可关闭菜单或阻塞点击区域 |

**失败取证：** 首个可重现步骤、出现/消失方向、短录制、系统设置、父 HWND 和对应日志。肉眼暂未发现延迟不等于严格零延迟；若逐帧比较，注明录制帧率与误差。本票不自动继承旧路线的 100 ms / 25 ms 指标。

结束后停止实例，恢复原自动隐藏设置。多屏、混合 DPI、HDR、独占全屏和不同 GPU/Windows 未测就保留未知。

## F. Explorer 重建后的安全失效

**前置：** 保存手头文件，确保方便重启桌面外壳；当前运行一个菜单 7 的实例。若现在不方便执行，此项保留未知。

1. 由你按 Ctrl+Shift+Esc 打开任务管理器，找到「Windows 资源管理器」，选择「重新启动」。任务栏/桌面会短暂重建；不要操作不相干的进程。
2. 观察旧实验安全停止，不出现崩溃对话框、孤儿控件、残余 Popup 或继续截获点击的区域。
3. 查看旧实例 summary.json 的 reason、exitCode 和 events.jsonl 的 cleanup。预期是检测到父 HWND/关系失效并停止；**应用退出码 3 可以是本项预期安全失效**，Run.ps1 因此报非零不等同于原生崩溃。必须同时核实清理与残留。
4. 回到菜单 7，重新列举并由你重新选择当前任务栏父级，启动新实例；旧 HWND 不复用。确认新实例正常。

**通过标准：** 安全失效、清理、无残留、显式新建四件事有证据。这里不要求无人值守自动恢复，也不会由脚本替你重启 Explorer。

**失败取证：** 重建前后时间、两次父 HWND、旧/新目录、弹窗或残留截图。不能因新窗口启动成功而省略旧实例清理检查。

## G. 性能验收（可以另一次完成）

先完成所需视觉/行为的关口，再决定运行。**性能阶段关闭动态背景动画、录屏和高频诊断**，保持电源模式、显示缩放、内容、材质、刷新负载相同。

菜单 8 输入 MEASURE 后，由你选择任务栏。默认 none / alpha 0.5 / 30 Hz，可见动态 600 秒。阶段为预热 5 秒 → 静态 10 秒 → 可见动态 600 秒 → 隐藏继续更新 20 秒 → 恢复 10 秒。

- 看到 hidden-data-updating 提示时，由你隐藏任务栏；完成后回到终端按 H，记录人工时点。看到 restored 提示时，由你恢复任务栏；完成后按 R。按键只记录报告时间，不控制或测得任务栏可见性；切换终端本身若改变任务栏状态，务必记下。
- 采样脚本没有把 Explorer 自动隐藏。phase 名称和 IsWindowVisible 都不能证明任务栏真的隐藏；实际隐藏/恢复时间与阶段错位必须写入观察表，受污染的阶段不能作为正确隐藏成本。
- Q 可以提前停止，但只有 summary.reason 为 measurement-complete 且各阶段实际时长满足要求，才是完整采样。
- 菜单会轮询日志给出提示，有额外进程/I/O 开销。它适合首轮人工采样；正式比较应一致地保留该开销，或用下面的直接入口并由人记录阶段时间，避免与没有监视器的旧数据直接相减。

直接命令如下；先从菜单列举结果取得当前屏幕名和 HWND，再填入命令。输出目录须为新的：

~~~powershell
& tools/TaskbarIslandLab/Run.ps1 -Mode explorer -Scenario measure -Monitor '填当前屏幕名' -ParentHwnd '填当前HWND' -Material none -Alpha 0.5 -Hz 30 -VisibleSeconds 600 -HiddenSeconds 20
~~~

票据性能矩阵还包含静态、1 Hz、60 Hz，以及 empty、top-level、owned 对照。Explorer 的 1 Hz、60 Hz 可使用上面直接命令更改 Hz 和可见时长（例如 20 秒）；保留完整分阶段记录和人工隐藏时点。30 Hz 的 Explorer 与匹配基线可见动态阶段各需至少 600 秒，不以短冒烟替代。

此前自有/顶级/empty 的 14 次配对已于 **2026-09-28** 完成，2026-10-01 做过证据回读；它们不是本轮 Explorer 测量。详见 [收尾验证](../../.scratch/二期开发/verification/05F/closeout-20261001/收尾验证.md)。当前环境或配置改变时，需要重新取得匹配基线；既有完整矩阵可通过以下入口重跑（通常超过 20 分钟，另有非 30 Hz 场景）：

~~~powershell
$pairedOutput = ".scratch/二期开发/verification/05F/manual-paired-$(Get-Date -Format yyyyMMdd-HHmmss-fff)"
& tools/TaskbarIslandLab/Measure-Pairs.ps1 -OutputDirectory $pairedOutput
~~~

人工性能判读至少填写：

1. Explorer 与匹配基线的目录、尺寸、DPI、材质、Hz、电源与背景负载；不一致处逐项说明。
2. 可见/隐藏/恢复的实际时间、请求更新数和实际内容更新数；Hz 不是实际呈现 FPS。
3. CPU 以单逻辑核心等效百分比为主，另列整机百分比及处理器数；不要把两种口径混比。
4. 私有内存、工作集、线程、句柄起止和趋势；持续增长不能仅看平均值。已有内存调查未证明“长期零泄漏”。
5. GPU、唤醒/上下文切换和呈现 FPS：现有工具未取得的指标明确写未测及原因，不填 0。需要时另做诊断，记录采集开销。
6. 由维护者决定常驻预算是否可接受，或保留待优化。当前没有可直接套用的绝对合格阈值。
